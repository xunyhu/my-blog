## 1. 使用的系统/方案

- **包管理器**: npm（由根目录 `package-lock.json` 与 `.yarn/` 目录并存可知，项目最初可能使用 Yarn，但当前锁定文件为 npm 生成）。
- **Node.js 版本约束**: 通过 `.nvmrc` 固定为 `22.14.0`。
- **构建工具链**: Next.js 16.1.7（App Router），TypeScript ^5，Tailwind CSS v4，ESLint 9，Prettier 3，Husky 9 + lint-staged 16。
- **无私有仓库或 vendoring 配置**: 未发现 `.npmrc`、`.yarnrc`、`pnpm-workspace.yaml`、`go.mod` 等私有源/工作区配置；所有依赖均从公共 registry 安装。

## 2. 关键文件

- `package.json`: 唯一声明式依赖清单，包含 `dependencies` 与 `devDependencies` 两组。
- `package-lock.json`: npm 生成的确定性锁文件，用于复现安装结果。
- `.nvmrc`: 指定 Node.js 运行时版本 `22.14.0`。
- `.husky/pre-commit`: Husky 钩子脚本（配合 `prepare: "husky"`）在提交前触发 lint-staged。

## 3. 架构与约定

- **依赖分组**: 运行期依赖（如 `next`、`react`、`gray-matter`、`rehype-*`、`remark-*`、`framer-motion`、`tailwindcss` 等）放入 `dependencies`；开发期工具（`typescript`、`eslint`、`prettier`、`@types/*`、`husky`、`lint-staged`）放入 `devDependencies`。
- **Next.js 生态对齐**: `next` 与 `eslint-config-next` 版本号严格一致（均为 `16.1.7`），避免 ESLint 规则与框架版本不匹配。
- **React 类型**: `@types/react` 与 `@types/react-dom` 使用 `^19`，与 `react`/`react-dom` 的 `19.2.3` 主版本对齐。
- **Markdown 渲染管线**: 通过 `gray-matter` + `remark` 生态（`remark-gfm`、`remark-html`）解析 frontmatter 与 Markdown，再经 `react-markdown` + `rehype-*` 插件（自动链接、高亮、slug）渲染到 React。
- **样式管线**: Tailwind CSS v4 + `@tailwindcss/postcss` + `@tailwindcss/typography`，与 `postcss.config.mjs`、`tailwind.config.js` 配合。
- **Git 钩子集成**: `scripts.prepare` 执行 `husky`，`lint-staged` 对 `*.{ts,tsx}` 运行 `tsc --noEmit` 与 `next lint --fix`，作为提交前的质量门禁。

## 4. 约定与约束

- **Node 版本**: 开发者需使用 `.nvmrc` 指定的 `22.14.0`（由 nvm/nvmf 等工具读取）。
- **依赖锁定**: 变更依赖后应提交 `package-lock.json`，以保证 CI 与本地安装结果一致。
- **Next.js 与 ESLint 版本绑定**: `next` 与 `eslint-config-next` 保持相同版本号（`16.1.7`），这是 Next.js 官方推荐的搭配方式。
- **无私有 registry / 代理配置**: 仓库中未出现 `.npmrc` 或等效配置，默认使用 npm 公共 registry。
- **无 monorepo/workspace 结构**: 单包项目，不存在 workspace 或子包依赖声明。
