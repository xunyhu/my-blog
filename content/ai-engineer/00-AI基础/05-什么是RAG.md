# 什么是RAG

## 一、是什么

**一句话：RAG（Retrieval-Augmented Generation，检索增强生成）是一种「先从外部知识库检索相关内容，再让 LLM 基于检索到的内容生成回答」的技术范式。**

通俗说：**开卷考试**。LLM 本身是「闭卷」（只靠训练时记住的知识），RAG 给它配了一本「可实时查阅的资料库」，让它「先查资料、再作答」。

```text
   纯 LLM（闭卷）：   问题 ─────────────────────────▶ 回答（凭记忆，可能过时/编造）

   RAG（开卷）：      问题 ──▶ 检索知识库 ──▶ 相关片段 ┐
                                                       ├──▶ LLM ──▶ 有依据的回答
                                    问题 ──────────────┘
```

## 二、为什么

RAG 精准命中了纯 LLM 的三大痛点：

```text
   痛点一：知识过时 —— 模型训练有截止日期，不知道之后发生的事
   痛点二：幻觉     —— 不知道答案时，LLM 可能「一本正经地编造」
   痛点三：私域缺失 —— 模型没见过你公司的内部文档/个人数据
```

RAG 的解法：把「最新、私有、专业」的知识放进**外挂知识库**，检索后作为依据喂给模型——

- **知识实时更新**：改知识库即可，无需重训模型。
- **降低幻觉**：回答「有据可查」，还能给出来源引用。
- **接入私域数据**：企业文档、个人笔记都能成为问答依据。
- **成本远低于微调**：不必训练模型，只需维护向量库。

> 一句话：**RAG 让 LLM 从「凭记忆答题」变成「查资料答题」，是企业级 AI 知识库、问答系统的事实标准。**

## 三、核心概念

### 1. 基本定义：检索 + 生成

RAG = **Retrieval（检索）** + **Augmented（增强）** + **Generation（生成）**：检索出相关内容，用它「增强」提示词，再让 LLM 生成回答。

### 2. 完整流程：两个阶段

```text
   【离线索引阶段】把知识库变成可检索的向量库
   文档 ──切分──▶ 文本块(chunk) ──Embedding──▶ 向量 ──存入──▶ 向量数据库

   【在线检索生成阶段】回答问题
   ┌────────┐ embed  ┌────────┐ 相似度检索 ┌─────────┐
   │ 用户问题│ ─────▶ │问题向量 │ ─────────▶ │ Top-K 块 │
   └────────┘        └────────┘            └────┬────┘
                                                 │ 拼进 Prompt
                                                 ▼
                                    ┌────────────────────────┐
                                    │ 提示词 = 问题 + 检索到的块 │──▶ LLM ──▶ 回答(+引用)
                                    └────────────────────────┘
```

三个关键环节：

```text
   ① 切分(Chunking)：把长文档切成合适大小的块（太大噪声多、太小语义碎）
   ② 检索(Retrieval)：用向量相似度找最相关的 K 块（常配合关键词做混合检索）
   ③ 生成(Generation)：把「问题 + 检索块」组织成 Prompt，让 LLM 据此作答
```

### 3. 关键特征

```text
   特征一：外挂知识 —— 知识在库里，不在模型参数里，可随时更新
   特征二：依赖检索质量 —— 检索不准，生成再好也是「garbage in, garbage out」
   特征三：可溯源 —— 能标注答案来自哪份文档，增强可信度
   特征四：与模型解耦 —— 换模型不必重建知识库（但换 Embedding 模型要重算向量）
```

### 4. 与其他概念的关系

```text
   Embedding（把文本变向量）──▶ 向量数据库（存/检索向量）──▶ RAG（检索+生成）
                                                              │
   RAG 也常被 Agent 当作一个「检索工具」来调用 ◀───────────────┘
```

- **RAG vs Embedding**：Embedding 是 RAG「检索」环节的技术手段（把文本向量化才能算相似度）。
- **RAG vs 微调（Fine-tuning）**：见下表，这是最常见的选型困惑。
- **RAG vs Agent**：RAG 可作为 Agent 的一个工具；Agent 更宽泛（还能调其它工具、多步行动）。

### 5. RAG vs 微调（Fine-tuning）

| 维度     | RAG（检索增强）            | 微调（Fine-tuning）          |
| -------- | -------------------------- | ---------------------------- |
| 知识注入 | 外挂知识库，**随时更新**   | 写进模型参数，**更新需重训** |
| 擅长     | 提供**事实性、时效性**知识 | 改变**风格、格式、领域语气** |
| 成本     | 低（维护向量库）           | 高（训练 + 算力）            |
| 可溯源   | ✅ 能给出来源              | ❌ 难溯源                    |
| 幻觉     | 较低（有据可查）           | 仍可能幻觉                   |
| 典型场景 | 企业知识库问答、客服       | 特定文风、专业术语风格       |

**经验**：需要「让模型知道它不知道的事实」→ RAG；需要「让模型学会某种风格/格式」→ 微调。二者也常结合。

## 四、直观示例

### 1. RAG 问答的最小实现（伪代码）

```typescript
async function ragAnswer(question: string): Promise<string> {
  // ① 把问题向量化
  const qVec = await embed(question);
  // ② 在向量库检索最相关的 3 个文档块
  const chunks = await vectorDB.search(qVec, { topK: 3 });
  // ③ 组织提示词：把检索到的内容作为「上下文」
  const prompt = `请仅根据以下资料回答问题，若资料中没有，请说"不知道"。

资料：
${chunks.map((c) => c.text).join('\n---\n')}

问题：${question}`;
  // ④ 让 LLM 基于资料生成
  return await llm.chat(prompt);
}
```

**关键技巧**：在提示词里明确要求「**仅根据资料回答、没有就说不知道**」，这是抑制幻觉的核心手段。

### 2. 检索质量决定成败

```text
   好检索 → 好回答：  问「退款政策」→ 检索到退款条款 → 准确回答
   坏检索 → 坏回答：  问「退款政策」→ 检索到无关内容 → LLM 只能瞎编或答非所问
   → RAG 优化 80% 的功夫在「检索」：切分策略、Embedding 模型、混合检索、重排序
```

## 五、常见误区

- **误区一：RAG 能彻底消除幻觉。** RAG 显著降低幻觉，但若检索不准、或 LLM 不老实遵循资料，仍可能编造。需配合「仅据资料回答 + 无据则说不知道 + 引用溯源」。
- **误区二：RAG 就是微调的替代品。** 二者解决不同问题：RAG 补「知识」，微调改「风格/能力」；不是二选一。
- **误区三：文档切得越大越全越好。** 块太大→噪声多、超上下文；太小→语义破碎。切分策略是 RAG 效果的关键变量。
- **误区四：只靠向量检索。** 向量擅长语义、弱于精确匹配（编号、专名）；生产环境常用**混合检索（向量 + BM25 关键词）+ 重排序**。
- **误区五：换了 Embedding 模型不用重算。** 不同模型向量空间不兼容，换模型必须对全库**重新 Embedding（re-index）**。

## 六、总结

- **RAG = 检索 + 生成**：先从外部知识库检索相关内容，再让 LLM 据此作答，相当于给模型「开卷考试」。
- 它解决纯 LLM 的**知识过时、幻觉、私域缺失**三大痛点，是企业知识库/问答系统的事实标准。
- 流程分**离线索引**（切分→Embedding→入向量库）与**在线检索生成**（问题→检索 Top-K→拼 Prompt→LLM 作答）。
- **检索质量决定 RAG 上限**，优化重心在切分、Embedding 选型、混合检索与重排序。
- **RAG 补知识、微调改风格**，二者互补而非替代。
