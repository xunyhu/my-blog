# 什么是Embedding

## 一、是什么

**一句话：Embedding（嵌入）是把文本、图像等「非结构化数据」映射成一串「高维数值向量」的技术——让语义相近的内容，在向量空间里距离也相近。**

计算机不能直接理解「猫」和「狗」的语义，但能把它们变成向量后**用数学计算相似度**。这就是 Embedding 的核心价值：**把「语义」翻译成「几何」。**

```text
   "国王"  ──Embedding──▶  [0.21, -0.53, 0.88, ..., 0.12]   （如 1536 维）
   "女王"  ──Embedding──▶  [0.19, -0.49, 0.85, ..., 0.15]   ← 与「国王」很近
   "苹果"  ──Embedding──▶  [-0.72, 0.31, -0.05, ..., 0.64]  ← 离得很远

   语义相近 → 向量方向相近 → 可用「距离/夹角」度量语义
```

## 二、为什么

- **让语义「可计算」**：Embedding 把模糊的「意思像不像」变成精确的「向量距离多少」，这是所有语义检索的前提。
- **RAG 的地基**：知识库检索（RAG）本质就是「把问题和文档都转成向量，找最近的几段」——没有 Embedding 就没有 RAG。
- **跨模态桥梁**：文本、图像可映射到同一向量空间，实现「以文搜图」。
- **推荐/聚类/去重**：相似内容推荐、文本聚类、重复检测，底层都靠向量相似度。

> 一句话：**如果 Token 是 LLM 的「字节」，那 Embedding 就是 AI 应用的「坐标系」**——它让机器第一次能「按意思」而非「按字面」来搜索和理解。

## 三、核心概念

### 1. 基本定义：稠密向量表示

Embedding 通常是一个**稠密（dense）浮点数向量**，维度常见 384 / 768 / 1536 / 3072：

```text
   稀疏表示（传统 one-hot）：  "猫" = [0,0,...,1,...,0,0]  （维度=词表大小，绝大多数是 0）
   稠密表示（Embedding）：     "猫" = [0.2, -0.5, 0.8, ...]（几百~几千维，每维都有值）
   稠密向量的每一维可理解为某种「潜在语义特征」的组合
```

### 2. 关键特征

```text
   特征一：语义相近 → 向量相近
           "汽车" 与 "轿车" 的向量距离，远小于 "汽车" 与 "香蕉"
   特征二：向量有「方向」和「长度」，通常关注方向（夹角）
   特征三：支持「语义算术」（经典案例）
           vec(国王) - vec(男人) + vec(女人) ≈ vec(女王)
   特征四：由专门的 Embedding 模型生成
           与生成文本的 LLM 不同，Embedding 模型只输出向量、不生成文字
```

### 3. 如何度量「相近」：余弦相似度

最常用的是**余弦相似度（Cosine Similarity）**——衡量两个向量**夹角**的余弦值，范围 [-1, 1]：

```text
   cos(θ) = (A · B) / (|A| × |B|)

   1.0  → 方向完全一致（语义几乎相同）
   0.8+ → 高度相关
   0.0  → 正交（无关）
   -1.0 → 完全相反
```

```text
        B(女王)
       /
      / θ 小 → cos 接近 1 → 语义近
     /
    A(国王) ────────▶ C(苹果)  θ 大 → cos 接近 0 → 语义远
```

### 4. 与其他概念的关系

```text
   Token（离散文字） ──Embedding模型──▶ Embedding（连续向量）
                                              │
                          ┌───────────────────┼───────────────────┐
                          ▼                   ▼                   ▼
                    向量数据库存储          语义检索(RAG)         相似度/聚类
                    （见《什么是RAG》）
```

- **Embedding vs Token**：Token 是「切出来的文字片段」，Embedding 是「把 Token 序列压成的一个向量」；前者离散、后者连续。
- **Embedding vs LLM**：LLM（生成模型）输出文字，Embedding 模型输出向量；RAG 里两者配合——Embedding 负责「检索」，LLM 负责「生成」。
- **Embedding vs 向量数据库**：Embedding 是「向量本身」，向量数据库是「高效存储和检索海量向量」的工具。

## 四、直观示例

### 1. 生成 Embedding 并算相似度

```typescript
// 以 OpenAI Embedding API 为例（伪代码）
async function embed(text: string): Promise<number[]> {
  const res = await openai.embeddings.create({
    model: 'text-embedding-3-small', // 输出 1536 维向量
    input: text,
  });
  return res.data[0].embedding;
}

// 余弦相似度
function cosine(a: number[], b: number[]): number {
  let dot = 0, na = 0, nb = 0;
  for (let i = 0; i < a.length; i++) {
    dot += a[i] * b[i]; na += a[i] ** 2; nb += b[i] ** 2;
  }
  return dot / (Math.sqrt(na) * Math.sqrt(nb));
}

const vCat = await embed('猫');
const vDog = await embed('狗');
const vCar = await embed('汽车');
cosine(vCat, vDog); // ≈ 0.6+  语义相近
cosine(vCat, vCar); // ≈ 0.1   语义无关
```

### 2. 语义检索的最小流程（RAG 雏形）

```text
   ① 离线：把知识库每段文档 → Embedding → 存入向量库
   ② 在线：用户问题 → Embedding → 在向量库找「最近的 K 段」
   ③ 把检索到的 K 段 + 问题一起喂给 LLM → 生成有依据的回答
   ┌────────┐  embed   ┌──────────┐  最近邻   ┌────────┐  生成  ┌──────┐
   │ 问题    │ ───────▶ │ 问题向量  │ ───────▶ │ Top-K 段│ ─────▶ │ LLM  │
   └────────┘          └──────────┘          └────────┘        └──────┘
```

这正是下一篇《什么是RAG》要展开的核心链路——**Embedding 让「按意思找资料」成为可能**。

## 五、常见误区

- **误区一：Embedding 向量是「唯一正确」的。** 同一段文本，不同 Embedding 模型给出的向量完全不同；**不能把 A 模型的向量拿去和 B 模型的向量比相似度**。
- **误区二：维度越高越好。** 高维不一定更准，反而增加存储与计算成本；应按任务在效果/成本间权衡。
- **误区三：Embedding 能理解「精确匹配」。** 向量检索擅长「语义相似」，但对「编号、ID、精确关键词」可能不如传统全文检索——所以生产中常用**混合检索（向量 + 关键词）**。
- **误区四：Embedding 模型就是 LLM。** 两者不同：LLM 生成文字，Embedding 模型只吐向量；RAG 中各司其职。
- **误区五：向量算出来就一劳永逸。** 换了 Embedding 模型，历史向量必须**全部重算（re-index）**，否则新旧向量不可比。

## 六、总结

- **Embedding 把非结构化数据映射为高维向量**，让「语义相近」变成「向量距离相近」，从而可被机器计算。
- 它是**语义检索、RAG、推荐、聚类、去重**的共同地基；RAG 的「检索」环节本质就是向量最近邻搜索。
- **余弦相似度**是最常用的语义度量（看方向夹角，范围 [-1,1]）。
- Embedding 由**专门的嵌入模型**生成，与生成文本的 LLM 分工不同；换模型必须重算全部向量。
- 向量检索擅长语义、弱于精确匹配，生产中常与关键词检索组成**混合检索**。

> Embedding 的深刻之处，在于它把「理解」这个看似玄妙的词，还原成了一个朴素的几何问题——**意思像不像，就看向量近不近**。当你能用一串数字表达「国王与女王的关系」，你就握住了让机器「按语义思考」的钥匙。这也是为什么，几乎所有现代 AI 应用的检索能力，都从一次 Embedding 开始。
