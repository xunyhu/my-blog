# 什么是Agent

## 一、是什么

**一句话：Agent（智能体）是一个以 LLM 为「大脑」，能够自主「感知 → 思考 → 行动 → 观察」循环、调用工具、分多步完成复杂目标的 AI 系统。**

普通 LLM 只会「说」——你问一句、它答一句；而 Agent 会「做」——它能拆解任务、调用工具、根据结果调整下一步，直到把事办成。

```text
   普通 LLM 调用：      提问 ──▶ 回答（一次性，只输出文字）
   Agent：              目标 ──▶ 规划 ──▶ 调工具 ──▶ 看结果 ──▶ 再决策 ──▶ … ──▶ 完成
                        └────────── 多步循环，能行动、能自我修正 ──────────┘
```

一个形象的类比：**LLM 是「大脑」，Agent 是「大脑 + 手 + 记忆 + 计划」的完整的人。**

## 二、为什么

- **突破 LLM 的能力边界**：LLM 本身不能联网、不能查数据库、不能执行代码、知识还会过时；Agent 通过「调用工具」补上这些短板。
- **完成多步复杂任务**：「帮我查天气再订个提醒」这类需要多步、有依赖的任务，单次问答做不到，Agent 能编排。
- **自主性与适应性**：Agent 能根据中间结果动态调整策略，而非走死流程。
- **AI 应用的进阶形态**：从「问答机器人」到「能干活的助手」，Agent 是关键一跃。

> 一句话：**LLM 让 AI「会思考」，Agent 让 AI「会做事」。** 它是把大模型从「聊天工具」变成「生产力」的核心范式。

## 三、核心概念

### 1. 基本定义：Agent 的四大组成

一个典型 Agent = **大脑 + 规划 + 记忆 + 工具**：

```text
   ┌─────────────────────── Agent ───────────────────────┐
   │                                                      │
   │   🧠 模型(LLM)      推理与决策的中枢                   │
   │   📋 规划(Planning) 把大目标拆成小步骤、决定下一步      │
   │   💾 记忆(Memory)   短期(对话上下文)+长期(向量库/外部)   │
   │   🔧 工具(Tools)    搜索/计算/调 API/执行代码/读写文件   │
   │                                                      │
   └──────────────────────────────────────────────────────┘
```

### 2. 关键特征：ReAct 循环

Agent 的核心运行机制是 **「推理（Reason）+ 行动（Act）」交替循环**，即 ReAct 范式：

```text
   目标：北京今天适合户外跑步吗？
   ┌─────────────────────────────────────────────┐
   │ Thought(思考)：我需要先查北京今天的天气         │
   │ Action(行动) ：调用 get_weather("北京")        │
   │ Observation(观察)：晴，气温 18℃，PM2.5=45      │
   │                                               │
   │ Thought(思考)：天气不错，但要看空气质量         │
   │ Action(行动) ：调用 get_aqi("北京")            │
   │ Observation(观察)：AQI 良                      │
   │                                               │
   │ Thought(思考)：信息够了，可以给结论             │
   │ Answer(回答) ：适合，建议清晨出行…             │
   └─────────────────────────────────────────────┘
   循环：Thought → Action → Observation → …，直到得出答案
```

### 3. 关键特征小结

```text
   特征一：自主性 —— 能自己决定「下一步做什么」，而非被动应答
   特征二：工具调用 —— 通过外部工具突破 LLM 自身能力边界
   特征三：多步循环 —— 感知-决策-行动反复迭代，直到完成目标
   特征四：自我修正 —— 能根据 Observation 调整策略（甚至纠错重试）
```

### 4. 与其他概念的关系

```text
   LLM（大脑）
     │  加上工具调用能力
     ▼
   Function Calling（让 LLM 输出「要调哪个函数、传什么参数」的机制）
     │  工具多了，需要标准化接入
     ▼
   MCP（标准化地给 Agent 提供工具/数据的协议）
     │  多步自主编排
     ▼
   Agent（能规划、记忆、循环行动的完整系统）
```

- **Agent vs LLM**：LLM 是 Agent 的大脑，但 Agent 还包含规划、记忆、工具与循环控制。
- **Agent vs Function Calling**：Function Calling 是「让模型能调用工具」的底层机制，Agent 是「用这套机制自主完成多步任务」的上层系统。
- **Agent vs MCP**：MCP 是「如何标准化地给 Agent 提供工具」的协议（见《什么是MCP》）。
- **Agent vs Workflow**：Workflow 是「预先编排好的固定流程」，Agent 是「运行时自主决定流程」——前者确定、后者灵活（见《什么是AI Workflow》）。

## 四、直观示例

### 1. Agent 循环的伪代码

```typescript
async function runAgent(goal: string, tools: Tool[]) {
  const memory: Message[] = [{ role: 'user', content: goal }];

  for (let step = 0; step < MAX_STEPS; step++) {
    // ① 让 LLM 基于当前记忆决定：回答，还是调用工具
    const resp = await llm.chat({ messages: memory, tools });

    // ② 若 LLM 要求调用工具
    if (resp.toolCalls) {
      for (const call of resp.toolCalls) {
        const result = await executeTool(call.name, call.args); // ③ 执行
        memory.push({ role: 'tool', content: result }); // ④ 观察结果入记忆
      }
      continue; // 回到循环，让 LLM 根据新观察再决策
    }

    // ⑤ 没有工具调用 = 得出最终答案
    return resp.content;
  }
}
```

### 2. 一个真实感的 Agent 场景

```text
   用户："帮我总结这篇论文，并把它加到我的知识库"
   Agent 自主拆解：
     1. 调用「读取文件」工具拿到论文内容
     2. 调用 LLM 生成摘要
     3. 调用「向量库写入」工具，把摘要 Embedding 后存入知识库
     4. 返回："已总结并入库，要点如下…"
   —— 用户只说了一句话，Agent 编排了多个工具、多步完成
```

## 五、常见误区

- **误区一：Agent = 聊天机器人。** 聊天机器人多是「一问一答」，Agent 的关键是**自主多步 + 工具调用 + 循环决策**，能力维度不同。
- **误区二：什么任务都上 Agent。** Agent 有不确定性、成本和延迟。简单、确定的任务用固定 Workflow 或直接调用更可靠——**别为了 Agent 而 Agent**。
- **误区三：Agent 一定比 Workflow 好。** Agent 灵活但难控、难预测；对流程固定的任务，Workflow 更稳、更省、更可复现。二者应按「任务是否需要自主决策」来选。
- **误区四：给 Agent 无限步数/无限工具。** 步数不设上限可能陷入死循环、烧钱；工具过多会让模型「选择困难」、误调。要设 MAX_STEPS、精简工具集。
- **误区五：忽视 Agent 的可观测与兜底。** Agent 的中间步骤要可追踪（日志/trace），失败要能降级——否则生产环境不可控。

## 六、总结

- **Agent 是以 LLM 为大脑，具备规划、记忆、工具调用能力，能自主「感知-决策-行动-观察」循环完成目标的系统。**
- 四大组成：**模型（大脑）+ 规划 + 记忆 + 工具**；核心机制是 **ReAct 循环**（思考→行动→观察→再思考）。
- 它让 AI 从「会说」进化到「会做」，通过工具突破 LLM 自身边界。
- **Agent vs Workflow** 是关键抉择：需要自主决策用 Agent，流程固定用 Workflow。
- 生产中要控制步数、精简工具、加可观测与兜底，避免不可控。

> Agent 代表了 AI 应用从「工具」到「代理」的范式跃迁：我们不再只是向模型提问，而是**交给它一个目标，让它自己想办法达成**。这背后是信任的转移——也正因如此，Agent 工程的核心挑战，从来不是「让它更聪明」，而是「让它的自主性可控、可观测、可兜底」。理解了这一点，你才算真正理解了 Agent。
