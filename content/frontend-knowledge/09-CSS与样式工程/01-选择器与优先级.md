# 选择器与优先级

## 一、是什么

CSS 的两个基础问题：**「样式作用到哪些元素」**（选择器 Selector）与**「多条规则冲突时谁赢」**（优先级 Specificity）。绝大多数「我的样式怎么没生效」的困惑，根源都在这两点。

```css
/*  选择器   {  声明块  }  */
  .card h2   { color: #333; }
  └───┬───┘
   选中 .card 内的所有 h2
```

- **选择器**：一段「模式」，浏览器据此匹配 DOM 元素。
- **优先级（特异性）**：一个权重值，当多条规则都命中同一元素的同一属性时，优先级高者胜出。
- **层叠（Cascade）**：重要性、优先级、书写顺序三者共同决定最终样式的算法——CSS 的「C」即 Cascade。

## 二、为什么

- **精确命中**：好的选择器让样式精准作用，避免误伤。
- **可预测**：理解优先级，才能预判冲突结果，不靠「试到生效为止」。
- **可维护**：合理的优先级策略（低特异性为主）让样式易覆盖、易扩展；失控的高特异性会让后续修改举步维艰。

> 一句话：选择器决定「谁被选中」，优先级决定「冲突时听谁的」，层叠决定「最终算什么」。三者是 CSS 心智的地基。

## 三、核心原理

### 1. 选择器分类

```css
/* 基础选择器 */
* {
} /* 通配 */
div {
} /* 类型/标签 */
.card {
} /* 类 */
#app {
} /* ID */
span,
x {
} /* 分组（逗号=或） */

/* 组合选择器 */
.a .b {
} /* 后代（任意层级） */
.a > .b {
} /* 子代（直接子级） */
.a + .b {
} /* 相邻兄弟（紧接的下一个） */
.a ~ .b {
} /* 通用兄弟（之后所有同级） */

/* 属性选择器 */
[type='text'] {
} /* 精确匹配 */
[href^='https'] {
} /* 以…开头 */
[class*='btn'] {
} /* 包含子串 */

/* 伪类 / 伪元素 */
a:hover {
} /* 伪类：状态（: 单冒号） */
p::first-line {
} /* 伪元素：部分（:: 双冒号） */
li:nth-child(2) {
} /* 结构伪类 */
```

### 2. 优先级四元组计算法

优先级是一个 **(a, b, c, d)** 四元组，从左到右比较（像版本号，高位大者胜）：

```text
   a  b  c  d
   │  │  │  └─ 类型选择器、伪元素           （div, p, ::before）
   │  │  └──── 类选择器、属性选择器、伪类    （.card, [type], :hover）
   │  └─────── ID 选择器                     （#app）
   └────────── 行内样式 style=""（写在标签上）
   另外：!important 凌驾于以上全部（单独一档）
```

**计算示例**（逐位比较，先比 a，相同再比 b……）：

| 选择器                | a   | b   | c   | d   | 说明                 |
| --------------------- | --- | --- | --- | --- | -------------------- |
| `*`                   | 0   | 0   | 0   | 0   | 通配符不计权重       |
| `li`                  | 0   | 0   | 0   | 1   | 1 个类型             |
| `ul li`               | 0   | 0   | 0   | 2   | 2 个类型             |
| `.card`               | 0   | 0   | 1   | 0   | 1 个类               |
| `.card li.active`     | 0   | 0   | 2   | 2   | 2 类 + 2 类型        |
| `#app`                | 0   | 1   | 0   | 0   | 1 个 ID              |
| `div#app .list li`    | 0   | 1   | 1   | 3   | 1 ID + 1 类 + 3 类型 |
| `style="..."`（行内） | 1   | 0   | 0   | 0   | 行内样式             |

**关键：不是十进制相加！** `(0,1,0,0)`（一个 ID）**永远大于** `(0,0,99,0)`（99 个类）——高位不为零就赢，低位再多也追不上。

```css
#nav .item a {
} /* (0,1,2,1) —— 因为有 ID，胜过下面 */
.header .menu ul li a.link {
} /* (0,0,4,3) —— 类再多也输给 ID */
```

### 3. 层叠（Cascade）：冲突解决的三步

当多条规则命中同一元素的同一属性，浏览器按此顺序裁决：

```text
① 重要性（Origin + !important）
   用户代理 !important > 用户 !important > 作者 !important
   > 作者普通声明 > 用户普通 > 用户代理普通
        │  同重要性则 ↓
② 优先级（Specificity）
   比较四元组，大者胜
        │  优先级相同则 ↓
③ 书写顺序（Order）
   后写的覆盖先写的（源码靠后者胜）
```

### 4. 继承（Inheritance）

部分属性会从父元素「继承」到子元素，主要是**文本相关**（`color`、`font-*`、`line-height`、`visibility`）；而**盒模型相关**（`margin`、`padding`、`border`、`width`）默认不继承。

```css
body {
  font-family: sans-serif;
} /* 后代文本自动继承字体 */

/* 强制控制继承 */
.child {
  color: inherit; /* 强制继承父级 */
  margin: initial; /* 恢复初始值 */
  padding: unset; /* 可继承属性=inherit，否则=initial */
}
```

### 5. 现代选择器对优先级的影响

CSS 新增的组合选择器改变了优先级写法：

```css
/* :is() —— 取参数中「优先级最高者」作为自身权重 */
:is(#id, .class) {
} /* 权重 = ID（0,1,0,0），因为 #id 最高 */

/* :where() —— 优先级恒为 0（不影响权重，适合「默认样式」） */
:where(.btn) {
} /* 权重 = 0，可被任意规则轻松覆盖 */

/* :has() —— 父选择器，权重取参数中最高者 */
.card:has(img) {
} /* 选中「含图片的卡片」 */
```

`:where()` 的「零优先级」特性非常有用——写重置/基础样式时用它，可确保业务样式轻松覆盖，无需和优先级搏斗。

## 四、实践

### 1. 优先级策略：尽量「扁平、低特异性」

```css
/* ❌ 高特异性地狱：越写越长，无法覆盖 */
#page .main .content .article p.text {
} /* (0,1,3,2) */

/* ✅ 用类，保持扁平、低特异性，易覆盖易维护 */
.article-text {
} /* (0,0,1,0) */
```

主流方法论（BEM、Tailwind 原子类）都在追求「**用单一类选择器 + 组织约定**」替代「靠嵌套提升特异性」，从根源避免优先级战争。

### 2. 调试优先级

浏览器 DevTools 的 Styles 面板会**列出所有命中规则、按优先级排序、划掉被覆盖的声明**，是排查「样式不生效」的第一工具。

## 五、常见误区

- **误区一：把优先级当十进制相加。** `(0,0,1,0)` 一个类 ≠ 10 分；它是**逐位比较**，一位 ID 胜过任意多个类。
- **误区二：靠 `!important` 解决冲突。** 它能赢一时，但会破坏层叠的正常秩序，导致后续只能用更多 `!important` 覆盖，陷入恶性循环。应回到「降低特异性」根治。
- **误区三：以为 `*` 通配符有优先级。** `*` 权重为 0；`*` 影响性能的说法在现代浏览器也基本过时。
- **误区四：行内样式无法被覆盖。** 行内 `style=""` 优先级 (1,0,0,0) 极高，但**作者 `!important` 仍能覆盖它**。
- **误区五：`:is()` 与 `:where()` 等价。** 二者选择能力相同，但 `:is()` 取参数最高权重、`:where()` 恒为 0——覆盖行为完全不同。

## 六、总结

- **选择器**决定样式作用范围，从基础的类型/类/ID，到组合（后代/子代/兄弟）、属性、伪类伪元素，再到现代的 `:is`/`:where`/`:has`。
- **优先级**是 `(a,b,c,d)` 四元组，**逐位比较而非相加**；ID 位压倒类位，类位压倒类型位。
- **层叠**按「重要性 → 优先级 → 书写顺序」三步裁决冲突；`!important` 是最强档但慎用。
- **继承**让文本类属性沿 DOM 树传递，可用 `inherit`/`initial`/`unset` 控制。
- 工程实践应追求**低特异性、扁平选择器**（BEM/原子类），从根源避免优先级战争。

> 优先级不是 CSS 的「陷阱」，而是它「层叠」本质的必然产物。真正的高手不会和优先级搏斗，而是**用克制的选择器设计，让冲突从一开始就不发生**——当你发现自己在数选择器权重、加 `!important` 时，往往说明样式架构本身需要重构了。
