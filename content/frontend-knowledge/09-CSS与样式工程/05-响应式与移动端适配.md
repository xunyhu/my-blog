# 响应式与移动端适配

## 一、是什么

**响应式设计（Responsive Design）指让同一套页面在不同尺寸的屏幕（手机、平板、桌面）上都能良好呈现。** 它不是一门单独技术，而是「流动布局 + 媒体查询 + 弹性单位 + 响应式媒体」的组合策略。

```text
   同一份 HTML/CSS
        │
   ┌────┼────┬────────┐
   ▼    ▼    ▼        ▼
 手机  平板  笔记本   大屏桌面
 360  768   1280     1920   ← 视口宽度不同，布局自适应
```

核心理念：**不是为每种设备做一版，而是让布局「流动」起来，用断点（breakpoint）在关键宽度处调整。**

## 二、为什么

- **设备碎片化**：屏幕尺寸从 320px 到 4K，写死像素必然在某处崩坏。
- **移动优先的流量现实**：多数站点移动访问占比过半，移动体验即门面。
- **SEO**：Google 采用移动优先索引，响应式（单一 URL）利于收录。
- **可维护**：一套代码适配全端，远比维护「PC 站 + M 站」省事。

> 本项目博客正文用 `max-width` + 相对单位约束阅读宽度，配合 Tailwind 的响应式前缀（`sm:`/`md:`/`lg:`）在不同视口调整排版——正是响应式的日常落地。

## 三、核心原理

### 1. viewport 配置：移动适配的前提

移动端浏览器默认会以「桌面宽度（如 980px）」渲染再缩放，必须用 meta 标签纠正：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

- `width=device-width`：视口宽度 = 设备逻辑宽度（而非默认 980px）。
- `initial-scale=1.0`：初始缩放 1:1。

**没有这行，所有响应式都无从谈起。**

### 2. 移动优先（Mobile-First）

先写移动端基础样式，再用 `min-width` 媒体查询**逐级增强**到大屏：

```css
/* 基础样式 = 移动端（默认，最小屏） */
.card {
  padding: 12px;
}

/* 平板及以上（≥768px）增强 */
@media (min-width: 768px) {
  .card {
    padding: 24px;
  }
}
/* 桌面及以上（≥1024px）再增强 */
@media (min-width: 1024px) {
  .card {
    max-width: 1200px;
    margin: 0 auto;
  }
}
```

```text
   移动优先（min-width，推荐）      桌面优先（max-width）
   基础=手机 ──▶ 逐级加宽增强        基础=桌面 ──▶ 逐级收窄降级
   ┌──┐ ┌───┐ ┌────┐                ┌────┐ ┌───┐ ┌──┐
   移动  平板  桌面                   桌面  平板  移动
   优点：基础样式最简洁、性能友好、符合「渐进增强」理念
```

**为什么移动优先**：移动端性能和屏幕最受限，先保证它最简可用，再向上叠加——符合「渐进增强」，也让基础 CSS 更小。

### 3. 断点（Breakpoint）设计

不要绑定具体设备，而应**在布局「看起来要坏掉」的宽度处设断点**。业界常用（Tailwind 默认）：

| 断点  | 宽度    | 典型场景   |
| ----- | ------- | ---------- |
| `sm`  | ≥640px  | 大手机横屏 |
| `md`  | ≥768px  | 平板       |
| `lg`  | ≥1024px | 笔记本     |
| `xl`  | ≥1280px | 桌面       |
| `2xl` | ≥1536px | 大屏       |

### 4. 现代视口单位：vw / vh / dvh / svh

```css
.hero {
  height: 100vh;
} /* 视口高度的 100% */
.full {
  width: 100vw;
} /* 视口宽度的 100% */
```

**移动端 `100vh` 的经典坑**：地址栏显示/收起时，`vh` 基于「地址栏收起后」的最大视口，导致底部内容被地址栏遮挡。现代方案用**动态视口单位**：

```css
.hero {
  height: 100dvh;
} /* dynamic vh：随地址栏伸缩实时变化（推荐） */
.hero {
  height: 100svh;
} /* small vh：始终以最小视口（地址栏展开）为准 */
.hero {
  height: 100lvh;
} /* large vh：始终以最大视口为准 */
```

```text
   100vh（旧）：按最大视口算，地址栏展开时底部被遮 ❌
   100svh     ：按最小视口算，永远完整可见（偏保守）
   100dvh     ：动态跟随，体验最佳 ✅（现代浏览器已广泛支持）
```

### 5. 相对单位：rem / em

```css
html {
  font-size: 16px;
} /* rem 的基准 */
.title {
  font-size: 2rem;
} /* = 32px，相对根字号 */
.card {
  padding: 1.5em;
} /* 相对「当前元素」字号 */
```

- **`rem`**：相对**根元素**字号，全局一致，适合字号/间距体系。
- **`em`**：相对**当前元素**字号，会嵌套累积，适合组件内局部比例。
- 用相对单位，配合根字号或媒体查询，可实现「整体缩放」的响应式。

### 6. clamp()：流体排版（无需断点）

`clamp(min, 理想值, max)` 让字号随视口**平滑缩放**，且被限制在上下限内：

```css
h1 {
  /* 最小 1.5rem，理想 4vw，最大 3rem —— 随视口平滑变化，无需媒体查询 */
  font-size: clamp(1.5rem, 4vw, 3rem);
}
.container {
  width: clamp(320px, 90%, 1200px); /* 宽度流体自适应 */
}
```

### 7. 容器查询（Container Queries）：组件级响应式

媒体查询基于**视口**，但组件可能被放在不同宽度的容器里。容器查询让组件**根据自身容器宽度**响应（现代 CSS 重要进展）：

```css
.card-wrapper {
  container-type: inline-size;
} /* 声明为查询容器 */

@container (min-width: 400px) {
  .card {
    flex-direction: row;
  } /* 容器够宽时，卡片自己变横向布局 */
}
```

```text
   媒体查询：看「浏览器视口」多宽  → 同一组件在不同位置无法差异化
   容器查询：看「组件所在容器」多宽 → 组件真正「自包含」地响应
```

## 四、实践：移动端适配要点

### 1. 响应式图片

```html
<img
  srcset="a-400.jpg 400w, a-800.jpg 800w"
  sizes="(max-width:600px) 400px, 800px"
  src="a-800.jpg"
  alt="…"
/>
```

配合 CSS `img { max-width: 100%; height: auto; }` 防止图片溢出容器。

### 2. 安全区适配（刘海屏/圆角）

```css
.footer {
  padding-bottom: env(safe-area-inset-bottom); /* 避开 Home 指示条 */
}
```

需 `<meta name="viewport" content="viewport-fit=cover, ...">` 配合。

### 3. 触摸与交互适配

```css
.tap {
  min-height: 44px;
  min-width: 44px;
} /* 触摸目标 ≥44×44px（Apple HIG） */
.no-select {
  -webkit-tap-highlight-color: transparent;
} /* 去移动端点击高亮 */
/* hover 只在支持的设备生效，避免移动端「粘滞 hover」 */
@media (hover: hover) {
  .btn:hover {
    background: #eee;
  }
}
```

### 4. 1px 边框问题

高 dpr 屏幕上 `1px` 会显得粗，可用 `transform: scaleY(0.5)` 的伪元素方案，或 `border-width: thin`。

## 五、常见误区

- **误区一：忘写 viewport meta。** 没有它，移动端按 980px 渲染，响应式全部失效。
- **误区二：桌面优先（max-width）层层覆盖。** 基础样式臃肿、移动性能差；应移动优先（min-width）渐进增强。
- **误区三：移动端无脑用 `100vh`。** 地址栏伸缩导致底部被遮；改用 `100dvh`/`100svh`。
- **误区四：断点绑定具体设备。** 设备千变万化，应按「布局断裂点」设断点，而非「iPhone 宽度」。
- **误区五：用 px 写死所有尺寸。** 丧失弹性；字号/间距优先 rem，宽度优先 % / fr / clamp。
- **误区六：忽略触摸目标大小。** 手机上 <44px 的按钮难点按，是常见的移动端体验硬伤。

## 六、总结

- 响应式 = **viewport 配置 + 流动布局 + 媒体查询断点 + 弹性单位 + 响应式媒体**的组合。
- **移动优先（`min-width`）** 是主流策略：基础样式服务最小屏，逐级增强。
- **视口单位**：移动端优先用 `dvh`/`svh` 替代有坑的 `vh`；**`clamp()`** 实现无断点的流体排版。
- **容器查询（`@container`）** 让组件按自身容器响应，是媒体查询的重要补充。
- 移动端细节：响应式图片、`safe-area` 安全区、≥44px 触摸目标、`@media (hover:hover)` 处理悬停、1px 边框。

> 响应式设计的思维演进，是从「**为不同设备做适配**」到「**让布局本身具备流动性**」：媒体查询是「在断点处切换」，而 `clamp()`、容器查询、`auto-fit` 网格则是「连续地自适应」。当你的布局能像水一样填满任何容器，媒体查询就从「必需品」退化为「锦上添花」——这才是响应式的终极形态：**不是应对每一种屏幕，而是根本不预设屏幕。**
