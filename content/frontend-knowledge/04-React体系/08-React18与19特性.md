# React18与19特性

## 一、是什么

React 18 与 19 是 React 走向「并发 + 全栈」的两代关键版本：

- **React 18（2022）** 的主线是**并发渲染（Concurrent Rendering）**——把「一次同步、不可打断」的渲染，改造成「可中断、可恢复、可分优先级」的调度，并以此为基础带来自动批处理、Transition、流式 SSR 等能力。
- **React 19（2024-12 stable）** 的主线是**以 Action 为中心的数据交互**——用 `use()`、`useActionState`、`useOptimistic` 等把「异步变更 + pending/error/乐观更新」标准化，并用 **React Compiler** 把过去手写的 `memo/useMemo/useCallback` 自动化。

> 一句话记忆：**18 打地基（并发），19 盖房子（Actions + 编译器）。** 二者叠加 Server Components，构成 2026 年 React 全栈开发的基线。

## 二、为什么

React 17 及以前是「同步渲染」：一次 `setState` 触发一次不可中断的递归渲染。组件树一大，主线程被长时间占用，输入卡顿、掉帧。

```text
同步渲染（React 17-）              并发渲染（React 18+）
┌──────────────────────┐          ┌────┐ ┌────┐ ┌────┐
│ 一次渲染到底，不可打断 │          │片段│→│片段│→│片段│  ← 可被高优先级任务打断
└──────────────────────┘          └────┘ └────┘ └────┘
  用户输入被阻塞 → 卡顿             紧急更新插队 → 跟手
```

React 18 的并发能力让「渲染」变成可调度的工作单元（详见本模块《Fiber 架构》）；React 19 则在此之上，把「和服务器交互的异步流程」也纳入统一范式，消除大量样板代码。

## 三、React 18 核心特性

### 1. 并发渲染与 createRoot

启用并发能力的前提是改用 `createRoot` API（而非旧的 `ReactDOM.render`）：

```jsx
// React 18+ 入口
import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root'));
root.render(<App />);
```

只有走 `createRoot`，Transition、Suspense 并发特性、自动批处理才会生效。

### 2. 自动批处理（Automatic Batching）

React 18 把「多次 setState 合并为一次渲染」从「仅事件处理器内」扩展到**所有场景**（Promise、setTimeout、原生事件回调中都批处理）：

```jsx
// React 18：以下两次更新只触发一次渲染（即便在 Promise 里）
fetchData().then(() => {
  setCount((c) => c + 1); // ┐ 自动合并
  setFlag((f) => !f);     // ┘ 一次 re-render
});
```

如确需立即刷新，可用 `flushSync` 强制同步提交（少用，会牺牲性能）。

### 3. Transition：区分「紧急」与「过渡」更新

用户输入是**紧急更新**（要立即响应），而由输入引发的大范围 UI 变化是**过渡更新**（可延后、可打断）。`useTransition` / `startTransition` 让你标记后者：

```jsx
import { useTransition } from 'react';

function Search() {
  const [query, setQuery] = useState('');
  const [list, setList] = useState([]);
  const [isPending, startTransition] = useTransition();

  function onChange(e) {
    setQuery(e.target.value);            // 紧急：输入框立即更新
    startTransition(() => {
      setList(filterHugeList(e.target.value)); // 过渡：大列表渲染可被打断
    });
  }
  return <>{isPending ? <Spinner /> : null}<List data={list} /></>;
}
```

`isPending` 让「过渡进行中」可视化，输入始终跟手。

### 4. useDeferredValue：延迟一个值

当你拿不到「更新动作」、只能拿到「值」时，用 `useDeferredValue` 延后某个值的更新，让昂贵渲染落后于紧急输入：

```jsx
const deferredQuery = useDeferredValue(query);
// 用 deferredQuery 渲染大列表；query 保持最新用于输入框
const list = useMemo(() => filterHugeList(deferredQuery), [deferredQuery]);
```

与 `useTransition` 的区别：Transition 包裹「更新动作」，`useDeferredValue` 包裹「值」，后者更适合无法改动更新源（如来自 props）的场景。

### 5. Suspense 与流式 SSR

React 18 让 `Suspense` 在服务端也能用，配合流式 SSR（`renderToPipeableStream`）实现**分块发送 + 选择性注水（selective hydration）**：先发送已就绪的 HTML 外壳，慢的部分包在 `<Suspense fallback>` 里稍后流入，且用户交互到的部分优先 hydrate。

### 6. useId

生成**在 SSR 与客户端保持一致**的唯一 ID，避免服务端/客户端 ID 不匹配导致的 hydration 警告：

```jsx
const id = useId();
return <><label htmlFor={id}>姓名</label><input id={id} /></>;
```

## 四、React 19 核心特性

### 1. use()：在渲染中读取 Promise / Context

`use()` 是 React 19 新 API，用于在渲染期间读取一个 Promise（配合 Suspense）或 Context。**它不是普通 Hook——可以在条件语句中调用**：

```jsx
import { use, Suspense } from 'react';

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise); // 挂起直到 Promise resolve
  return comments.map((c) => <p key={c.id}>{c.text}</p>);
}

function Page({ commentsPromise }) {
  return (
    <Suspense fallback={<div>加载中…</div>}>
      <Comments commentsPromise={commentsPromise} />
    </Suspense>
  );
}
```

### 2. Actions 三剑客：useActionState / useFormStatus / useOptimistic

React 19 把「表单/异步变更」抽象为 **Action**（一个函数，通常在 Server Action 或异步提交中使用），并配套三个 Hook：

```jsx
import { useActionState } from 'react'; // 曾用名 useFormState

async function submitName(prevState, formData) {
  const name = formData.get('name');
  const error = await updateName(name);
  if (error) return { error };
  return { success: true };
}

function NameForm() {
  // [state, formAction, isPending] = useActionState(action, initialState)
  const [state, formAction, isPending] = useActionState(submitName, null);
  return (
    <form action={formAction}>
      <input name="name" disabled={isPending} />
      <button disabled={isPending}>提交</button>
      {state?.error && <span>{state.error}</span>}
    </form>
  );
}
```

- **`useActionState`**：管理 Action 的返回状态 + `isPending`，把「提交中/成功/失败」样板一次性收敛。
- **`useFormStatus`**：在**子组件**里读取父 `<form>` 的提交状态（如通用的提交按钮），无需层层传 props。
- **`useOptimistic`**：乐观更新——先立即展示预期结果，后台真正提交，失败再回滚：

```jsx
import { useOptimistic } from 'react';

function MessageList({ messages, sendMessage }) {
  const [optimistic, addOptimistic] = useOptimistic(messages, (cur, text) => [
    ...cur, { text, sending: true },
  ]);
  async function formAction(formData) {
    addOptimistic(formData.get('text')); // 立即上屏
    await sendMessage(formData);         // 后台发送
  }
  return <form action={formAction}>{/* 渲染 optimistic */}</form>;
}
```

### 3. ref as prop：告别 forwardRef

React 19 中，**函数组件可直接把 `ref` 当普通 prop 接收**，不再需要 `forwardRef` 包裹（`forwardRef` 已弃用，未来将移除）：

```jsx
// React 19：直接用 ref prop
function Input({ placeholder, ref }) {
  return <input ref={ref} placeholder={placeholder} />;
}
// 使用：<Input ref={inputRef} />  —— 无需 forwardRef
```

### 4. React Compiler：自动记忆化

**React Compiler（1.0 已发布，Next.js 16 内置 stable 支持）** 在编译期自动为组件与值插入记忆化，从根源减少不必要的重渲染——**过去手写的 `React.memo`/`useMemo`/`useCallback` 大多不再需要**：

```ts
// next.config.ts
const nextConfig = { reactCompiler: true }; // 需装 babel-plugin-react-compiler
export default nextConfig;
```

它遵循「React 规则」（组件/Hook 需为纯函数），不合规处会自动跳过编译，可渐进采用。

### 5. 其他实用改进

- **`<Context>` 直接作 Provider**：可写 `<ThemeContext value="dark">` 代替 `<ThemeContext.Provider>`。
- **文档元数据**：组件内可直接渲染 `<title>`/`<meta>`/`<link>`，React 自动提升到 `<head>`。
- **资源预加载 API**：`preload`/`preinit`/`prefetchDNS` 等，在组件中声明式管理资源加载优先级。

### 6. React 19.2（2025-10）

- **View Transitions**（`<ViewTransition>`）：为更新/导航中的元素加过渡动画。
- **`useEffectEvent`**：把 Effect 里的「非响应式逻辑」抽成可复用事件函数，减少依赖数组心智负担。
- **`<Activity/>`**：以 `display:none` 隐藏 UI 但保留状态、清理 Effect，用于「后台活动」场景。

## 五、直观示例：一个综合搜索框

下面把 18 的 Transition 与 19 的 useOptimistic/Action 心智串起来：

```jsx
function SearchPage() {
  const [query, setQuery] = useState('');
  const [isPending, startTransition] = useTransition(); // 18
  const deferred = useDeferredValue(query);             // 18
  const results = useMemo(() => search(deferred), [deferred]);

  return (
    <>
      <input value={query} onChange={(e) => {
        setQuery(e.target.value);                        // 紧急：输入跟手
        startTransition(() => {/* 过渡：结果渲染可打断 */});
      }} />
      {isPending ? <Spinner /> : <ResultList data={results} />}
    </>
  );
}
```

要点：**输入用紧急更新保证跟手，结果渲染用 Transition + useDeferredValue 降级为可打断的过渡更新**，大列表也不卡输入。

## 六、常见误区

- **误区一：升级 React 18 就自动获得并发。** 必须改用 `createRoot`；旧的 `ReactDOM.render` 仍是同步模式。
- **误区二：`useTransition` 和 `useDeferredValue` 二选一即可。** 前者包裹「更新动作」、后者包裹「值」；拿不到更新源（值来自 props）时用 `useDeferredValue`。
- **误区三：React 19 里还要写 `forwardRef`。** 函数组件已可直接接收 `ref` prop，`forwardRef` 弃用。
- **误区四：开了 React Compiler 就能乱写。** Compiler 依赖「组件/Hook 为纯函数」的 React 规则；副作用、可变外部状态仍会破坏正确性，只是省掉了手动 memo。
- **误区五：`useActionState` 就是老的 `useFormState`。** 是同一个 API 的更名（stable 版定名 `useActionState`），旧名不再维护。
- **误区六：`use()` 要遵守 Hook 规则不能放条件里。** 恰恰相反，`use()` 是特例，**可以在条件/循环中调用**（但仍只能在组件或 Hook 内、不能在 try/catch 中）。

## 七、总结

- **React 18 = 并发地基**：`createRoot` 启用并发，自动批处理、`useTransition`/`useDeferredValue` 分离紧急与过渡更新，流式 SSR + 选择性注水，`useId` 保证同构 ID。
- **React 19 = Actions + 编译器**：`use()` 在渲染中读 Promise/Context，`useActionState`/`useFormStatus`/`useOptimistic` 标准化异步变更，`ref as prop` 取代 `forwardRef`，**React Compiler** 自动记忆化。
- **19.2** 补齐 View Transitions、`useEffectEvent`、`<Activity/>` 等体验/控制能力。
- 与本模块《Fiber 架构》《服务端组件 RSC》联动：Fiber 是并发的底层，RSC 是全栈的边界，18/19 特性则是这套体系面向日常开发的 API 表达。

> 从 18 到 19，React 的演进方向始终一致：**把「何时渲染、如何异步、要不要 memo」这些性能与状态心智，从开发者手里，逐步交给框架与编译器。**
