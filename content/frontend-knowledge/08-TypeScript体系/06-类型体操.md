# 类型体操

## 一、是什么

**「类型体操」（Type Gymnastics）指用 TypeScript 的类型系统进行「编程」**：把类型当作数据和逻辑，在**编译期**完成计算、变换、甚至字符串解析——尽管运行时这些类型早已被擦除。

支撑类型体操的，是四块积木：

```text
① 条件类型    T extends U ? X : Y      —— 类型层的「if / 三元」
② 映射类型    { [K in T]: ... }         —— 类型层的「for 遍历」
③ 模板字面量  `get${Capitalize<K>}`     —— 类型层的「字符串拼接」
④ infer       ... extends (infer U)     —— 类型层的「解构 / 模式匹配」
   + 递归：类型引用自身                    —— 类型层的「循环 / 递归」
```

有了这四块，类型系统就具备了接近「图灵完备」的表达力——能算，也能算到让人看不懂。因此本篇既讲「怎么做」，也讲「**该不该做**」。

## 二、为什么

- **精确建模**：把「运行时才知道形状」的数据（如 JSON 配置、路由、i18n key）在编译期就精确约束住。
- **零运行时开销**：所有计算在编译期完成，产物 JS 不含任何痕迹。
- **库作者刚需**：像 `zod`、`tRPC`、`Redux Toolkit` 的类型魔法，本质都是类型体操——理解它才能读懂/维护这类库。
- **面试与进阶**：类型体操是区分「会用 TS」与「精通 TS」的分水岭。

> 但务必记住：**类型体操是给「库作者」和「边界建模」用的重器，不是日常业务代码的常态。** 业务里过度体操，等于给同事（和三个月后的自己）埋天书。

## 三、核心原理

### 1. 条件类型 + 分发：类型层的 if

```ts
type IsString<T> = T extends string ? true : false;

type A = IsString<'hi'>; // true
type B = IsString<123>; // false
```

**分发特性**：当 `T` 是「裸类型参数」且为联合时，会逐成员计算再合并：

```ts
type ToArray<T> = T extends any ? T[] : never;
type C = ToArray<string | number>; // string[] | number[]（分发，而非 (string|number)[]）

// 想禁止分发，用元组包裹
type ToArrayNoDist<T> = [T] extends [any] ? T[] : never;
type D = ToArrayNoDist<string | number>; // (string | number)[]
```

### 2. infer：类型层的解构

`infer` 在条件类型的「模式」里挖槽，匹配成功后把槽内类型绑定出来：

```ts
type Unwrap<T> = T extends Promise<infer U> ? U : T; // 解 Promise
type First<T> = T extends [infer F, ...any[]] ? F : never; // 解元组首项
type Params<T> = T extends (...a: infer P) => any ? P : never; // 解函数参数

type F = First<[string, number]>; // string
```

可以多次 `infer`，甚至从字符串里「解构」：

```ts
// 提取 "a.b.c" 的第一段
type Head<S extends string> = S extends `${infer H}.${string}` ? H : S;
type H = Head<'user.name.first'>; // 'user'
```

### 3. 映射类型 + 键重映射（as）

映射类型遍历键，`as` 子句还能**改写键名、甚至过滤键**（映射成 `never` 即剔除）：

```ts
// 基础映射
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface Person {
  name: string;
  age: number;
}
type PersonGetters = Getters<Person>;
// { getName: () => string; getAge: () => number }
```

```text
   [K in keyof T as `get${Capitalize<K>}`]
    └─┬─┘      └────────┬────────┘
    遍历键            重映射：改写键名（get + 首字母大写）
   若 as 结果为 never，该键被剔除（过滤能力）
```

```ts
// 用 as + never 过滤：只保留函数属性
type OnlyFunctions<T> = {
  [K in keyof T as T[K] extends Function ? K : never]: T[K];
};
```

### 4. 模板字面量类型：类型层的字符串运算

```ts
type EventName<T extends string> = `${T}Changed`;
type E = EventName<'name'>; // 'nameChanged'

// 与联合结合会「笛卡尔积」展开
type Color = 'red' | 'blue';
type Size = 'sm' | 'lg';
type Combo = `${Color}-${Size}`; // 'red-sm' | 'red-lg' | 'blue-sm' | 'blue-lg'

// 内置字符串变换可组合
type Shout<S extends string> = Uppercase<S>;
```

### 5. 递归类型：类型层的循环

类型可以引用自身，实现「深度」变换：

```ts
// DeepReadonly：递归把每一层都变只读
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

// DeepPartial：递归可选（《工具类型》提过）
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;
```

```text
   DeepReadonly<{ user: { name: string } }>
     = { readonly user: DeepReadonly<{ name: string }> }
                              ↓ 递归展开
     = { readonly user: { readonly name: string } }
```

## 四、实践：几道经典体操

### 1. 键名风格转换：camelCase → snake_case

```ts
// 把驼峰键转成下划线键（利用模板字面量 + infer 拆字符串）
type ToSnake<S extends string> = S extends `${infer H}${infer T}`
  ? T extends Uncapitalize<T>
    ? `${Lowercase<H>}${ToSnake<T>}` // 小写字符，直接接
    : `${Lowercase<H>}_${ToSnake<Uncapitalize<T>>}` // 大写字符，插下划线
  : S;

type Snake = ToSnake<'userName'>; // 'user_name'
```

### 2. 字符串 Split：把 "a,b,c" 变元组

```ts
type Split<
  S extends string,
  D extends string,
> = S extends `${infer H}${D}${infer T}` ? [H, ...Split<T, D>] : [S];

type Parts = Split<'a,b,c', ','>; // ['a', 'b', 'c']
```

### 3. 路径参数提取：'/user/:id/post/:pid' → 'id' | 'pid'

```ts
type ExtractParams<Path extends string> =
  Path extends `${string}:${infer P}/${infer Rest}`
    ? P | ExtractParams<`/${Rest}`>
    : Path extends `${string}:${infer P}`
      ? P
      : never;

type Params = ExtractParams<'/user/:id/post/:pid'>; // 'id' | 'pid'
```

这类技巧正是 `tRPC`、类型安全路由库的底层——**把 URL 结构提升为编译期类型**。

### 4. 何时该「止步」

```ts
// ❌ 过度体操：业务里为了炫技把简单需求写成天书
type VeryComplex<...> = ... // 50 行嵌套条件类型

// ✅ 同一需求，用「值 + typeof 反推」往往更简单可维护
const config = { /* … */ } as const;
type Config = typeof config;
```

**判断准则**：如果一段类型体操，团队里除了你没第二个人能读懂、且没有对应的复用价值（不是库边界），那就应该退回「用值推导类型」或运行时校验（zod）。

## 五、常见误区

- **误区一：体操越强越好，到处秀。** 类型体操的**可维护性成本极高**，晦涩的类型报错会让同事崩溃。业务代码以「清晰」优先。
- **误区二：忽视编译性能。** 深度递归、大范围笛卡尔积展开会显著拖慢 `tsc`，甚至触发「Type instantiation is excessively deep」错误（TS 有递归深度上限）。
- **误区三：条件类型默认都分发。** 分发只对**裸类型参数**生效；需要整体判断时用 `[T] extends [U]` 包裹（见原理 1）。
- **误区四：用体操替代运行时校验。** 类型体操再强也只在编译期，`JSON.parse`/接口数据仍需 zod 等运行时校验，二者不能互相替代。
- **误区五：递归不设终止条件。** 递归类型必须有「基例」（如 `T extends object ? ... : T`），否则无限展开报错。

## 六、总结

- 类型体操 = 用**条件类型（if）、映射类型（for）、模板字面量（字符串）、`infer`（解构）、递归（循环）** 在编译期对类型编程。
- **分发**与 `[T] extends [U]` 的包裹、**`as` 重映射 + `never` 过滤**、**`infer` 拆字符串/元组**是三大高频手法。
- 它的正当战场是**库设计、边界建模**（路由、i18n key、schema 推导），而非日常业务。
- 代价是**可维护性与编译性能**：过度递归会拖慢 `tsc`、晦涩报错会劝退同事。
- 能用「值 + `typeof` 推导」或运行时校验更简单解决时，就别体操。

> 类型体操像一把锋利的双刃剑：它证明了 TypeScript 类型系统的表达力惊人——几乎是一门独立的函数式语言；但它也考验工程师的**克制**。真正的类型高手，不是能写多复杂的类型，而是**知道何时该写、何时该停**。让复杂留给库，让清晰留给业务。
