# 泛型

## 一、是什么

**泛型（Generics）是「类型的参数」。** 它让你在定义函数、接口或类时，先留一个类型的「占位符」，等到真正调用/使用时再填入具体类型——从而写出一份**既通用、又不丢失类型信息**的代码。

```ts
// 不用泛型：要么写死类型，要么退化成 any
function identityNumber(x: number): number {
  return x;
} // 只能处理 number

// 用泛型：T 是类型参数，调用时确定
function identity<T>(x: T): T {
  return x;
}

const a = identity<string>('hi'); // a: string
const b = identity(42); // b: number（自动推导，无需显式传）
```

`<T>` 就是泛型的标志。它像函数的形参，只不过传递的是**类型**而非值。

```text
   普通参数：   function f( x )        → 调用 f( 1 )       传入「值」
   泛型参数：   function f<T>( x:T )   → 调用 f<number>(1)  传入「类型」
                        ↑ 类型占位符            ↑ 类型实参
```

## 二、为什么

泛型解决的核心矛盾是：**「代码复用」与「类型安全」的兼得**。没有泛型时，要写通用函数只有两条路，都不理想：

```ts
// 路线 A：为每种类型写一份——重复、难维护
function firstOfNumber(arr: number[]): number {
  return arr[0];
}
function firstOfString(arr: string[]): string {
  return arr[0];
}

// 路线 B：用 any——通用了，但类型信息全丢，等于放弃检查
function first(arr: any[]): any {
  return arr[0];
}
const x = first([1, 2, 3]); // x: any —— 之后 x.abc 都不报错，失去保护

// 路线 C：泛型——一份代码，类型随输入而变，安全又复用 ✅
function first<T>(arr: T[]): T {
  return arr[0];
}
const y = first([1, 2, 3]); // y: number —— 类型被精确保留
```

```text
        通用性  │  类型安全
any       高    │    ✗（放弃检查）
重载       低    │    ✓（但要写 N 份）
泛型       高    │    ✓（一份搞定）  ← 两全其美
```

> 一句话：**`any` 是「我不要类型了」，泛型是「我现在还不知道类型，但用的时候会知道，到时候请帮我守住它」。**

## 三、核心原理

### 1. 泛型函数

类型参数可出现在**参数、返回值、函数体**的任意位置，形成类型间的关联：

```ts
// 返回值类型 = 参数类型（T 把输入输出「锁」在一起）
function wrap<T>(value: T): T[] {
  return [value];
}

// 多个类型参数
function pair<K, V>(key: K, value: V): [K, V] {
  return [key, value];
}

// 泛型 + 函数类型参数
function callWith<T, R>(fn: (x: T) => R, arg: T): R {
  return fn(arg);
}
```

调用时通常**无需手写类型实参**——TS 会根据传入的实参自动推导（见《类型推导》）：

```ts
wrap('hello'); // 推导 T = string，返回 string[]
pair('id', 1); // 推导 K = string, V = number，返回 [string, number]
```

### 2. 泛型接口与类型别名

```ts
// 泛型接口：常见的「统一 API 响应」包装
interface ApiResponse<T> {
  code: number;
  data: T; // data 的类型由使用时的 T 决定
  message: string;
}

interface User {
  id: number;
  name: string;
}

const res: ApiResponse<User> = {
  code: 0,
  data: { id: 1, name: 'Tom' },
  message: 'ok',
};
const res2: ApiResponse<User[]> = {
  code: 0,
  data: [
    /* … */
  ],
  message: 'ok',
};
```

```ts
// 泛型类型别名：可辨识联合 + 泛型
type Result<T, E = Error> = { ok: true; value: T } | { ok: false; error: E };
```

### 3. 泛型约束（extends）：给类型参数「划范围」

不加约束的 `T` 是「任意类型」，此时不能假设它有任何成员。用 `T extends X` 限定 `T` 必须满足某种结构：

```ts
// ❌ T 是任意类型，.length 可能不存在
function bad<T>(x: T) {
  return x.length;
} // 报错

// ✅ 约束 T 必须有 length
function getLength<T extends { length: number }>(x: T): number {
  return x.length;
}
getLength('str'); // ✅ string 有 length
getLength([1, 2, 3]); // ✅ 数组有 length
getLength({ length: 5 }); // ✅
getLength(123); // ❌ 报错：number 没有 length
```

```text
约束前：T = 任意类型        ┌─────────────┐
                            │  什么都可能是 │  → 不能访问任何成员
                            └─────────────┘
约束后：T extends {length}  ┌─────────────┐
                            │ 必须有 length │  → 可安全访问 .length
                            └─────────────┘
        传入的类型必须落在这个「圈」内
```

### 4. keyof 约束：泛型的黄金搭档

`keyof T` 得到 `T` 的所有键的联合，配合 `extends` 可实现「按 key 取值且类型精确」：

```ts
function pick<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]; // 返回类型是 T[K]——「key 对应的值类型」
}

const user = { id: 1, name: 'Tom', active: true };
pick(user, 'name'); // 返回类型 string
pick(user, 'id'); // 返回类型 number
pick(user, 'age'); // ❌ 报错：'age' 不在 keyof user 中
```

这里 `T[K]` 是**索引访问类型**，`K extends keyof T` 保证 key 合法，二者组合让「动态取属性」也享有完整类型安全——这是泛型最有威力的模式之一。

### 5. 默认类型参数

像函数默认值一样，泛型参数可给默认值，使用方不传时采用默认：

```ts
function createArray<T = string>(len: number, fill: T): T[] {
  return Array(len).fill(fill);
}
createArray(3, 'a'); // T 推导为 string
createArray<number>(3, 0); // 显式指定 T = number
```

### 6. 泛型类

```ts
class Stack<T> {
  private items: T[] = [];
  push(item: T): void {
    this.items.push(item);
  }
  pop(): T | undefined {
    return this.items.pop();
  }
}
const numStack = new Stack<number>(); // 实例化时确定 T
```

## 四、实践

### 1. 泛型 + 约束表达「配置对象」

```ts
// 只允许传入 config 已有的键，且返回值类型精确
function getConfig<T extends Record<string, unknown>, K extends keyof T>(
  config: T,
  key: K,
): T[K] {
  return config[key];
}
```

### 2. 泛型函数类型：描述「一类函数」

```ts
// 一个通用的「映射函数」类型
type Mapper<T, R> = (item: T, index: number) => R;

function mapArray<T, R>(arr: T[], fn: Mapper<T, R>): R[] {
  return arr.map(fn);
}
mapArray([1, 2, 3], (n) => n.toFixed(2)); // 推导 R = string，返回 string[]
```

### 3. 与本项目呼应

本项目 `lib/` 的数据层就大量依赖「输入 slug、输出结构化数据」的函数，用泛型可把 `ApiResponse<T>`、`Result<T>` 这类包装类型复用到位——一份定义，处处精确。

## 五、常见误区

- **误区一：泛型 = 高级 any。** 恰恰相反，泛型的价值就是**在通用中保住类型**；`any` 是放弃类型。若一个泛型从头到尾没用到 `T` 的约束、也没体现在返回类型上，那它可能根本不需要泛型。
- **误区二：约束写太宽或太窄。** `T extends any` 等于没约束；约束过窄又限制复用。应按「函数体真正用到的成员」来定约束（用到 `.length` 就约束 `{ length: number }`）。
- **误区三：能推导却硬写类型实参。** `identity<string>('hi')` 通常可简化为 `identity('hi')`，让 TS 推导；显式传参只在推导不出或需覆盖时才用。
- **误区四：泛型参数越多越好。** 每个 `<T, U, V>` 都增加心智负担，能被推导或与彼此关联的就别独立暴露。
- **误区五：以为泛型在运行时存在。** 泛型同样被**类型擦除**，`Stack<number>` 与 `Stack<string>` 运行时是同一个类，不能靠泛型参数做运行时分支判断。

## 六、总结

- 泛型是**类型的参数**，让一份代码适配多种类型，同时**不丢失类型安全**——这是它相对 `any` 与重载的核心优势。
- 类型参数可出现在函数、接口、类型别名、类中，把输入、输出、成员的类型「关联」起来。
- **泛型约束 `extends`** 给类型参数划定能力范围；**`keyof` + 索引访问 `T[K]`** 是「安全操作对象键」的黄金组合。
- 默认类型参数让泛型更易用；调用时优先依赖推导，少写显式实参。
- 泛型是编译期机制，运行时同样被擦除。

> 泛型的精髓，是**把「类型」当成可编程的变量**：先声明「我依赖某个尚未确定的类型 T」，再让调用方在使用时填入。掌握它，才真正迈入 TypeScript 从「标注类型」到「设计类型」的门槛——后续的《工具类型》《类型体操》，本质都是泛型与条件类型的组合运用。
