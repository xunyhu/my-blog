# 类型推导

## 一、是什么

**类型推导（Type Inference）是 TypeScript 在没有显式类型标注时，自动推断出表达式类型的能力。** 你不必处处写 `: number`，编译器会根据值、上下文、函数签名自己「算」出来。

```ts
let n = 42; // 推导为 number（没写 : number）
let s = 'hi'; // 推导为 string
const c = 'hello'; // 推导为字面量 'hello'（注意：const 更窄！）
let arr = [1, 2, 3]; // 推导为 number[]

function add(a: number, b: number) {
  return a + b; // 返回类型自动推导为 number
}
```

类型推导是 TS「少写标注却不失安全」的关键——**好的 TS 代码不是标注越多越好，而是让编译器尽可能替你推导，只在关键处显式声明。**

```text
   显式标注      let n: number = 42;    ← 你告诉编译器
   类型推导      let n = 42;            ← 编译器告诉你
                        结果相同，但推导更简洁、且随赋值自动更新
```

## 二、为什么

- **减少冗余**：`const total = price * count` 无需写 `: number`，一目了然还不会写错。
- **保持同步**：改了初始值，推导类型自动变化；手写标注反而可能与实际脱节。
- **精准胜于标注**：很多场景推导出的类型比人手写的更精确（如 `const` 的字面量类型）。
- **契约点显式化**：把标注留给「函数参数/返回值」这类真正的对外契约，其余交给推导，代码信噪比更高。

> 经验法则：**变量能推导就别标注；函数签名（参数、返回值）应显式标注。** 前者是局部实现细节，后者是对外承诺。

## 三、核心原理

### 1. 基础推导与「最佳公共类型」

从多个候选中，TS 会推断出一个能兼容全部的「最佳公共类型」：

```ts
let x = [1, 'a', true]; // (string | number | boolean)[]
```

### 2. 字面量拓宽（Widening）

同样是字符串，`const` 与 `let` 推导结果不同——这是初学者最常困惑的点：

```ts
const a = 'hello'; // 类型是字面量 'hello'（const 不可再赋值，保留最窄类型）
let b = 'hello'; // 类型是 string（let 可变，拓宽为 string）
```

```text
   const a = 'hello'  →  a: 'hello'   （窄：只能是这个值）
   let   b = 'hello'  →  b: string    （宽：可被重新赋值成别的字符串）
        原因：let 变量未来可能变化，TS 主动「拓宽」到基础类型
```

对象属性同理会被拓宽：

```ts
const obj = { kind: 'circle' }; // obj.kind: string（属性可改，拓宽了）
```

### 3. const 断言（as const）：冻结为最窄类型

当你需要**保留字面量类型、且让对象只读**时，用 `as const`：

```ts
const cfg = { mode: 'dark', size: 10 } as const;
// cfg.mode: 'dark'（不是 string），且整个对象 readonly

const dirs = ['up', 'down'] as const;
// dirs: readonly ['up', 'down']（元组 + 字面量，而非 string[]）

type Mode = typeof cfg.mode; // 'dark'
```

`as const` 在定义常量映射、动作类型、可辨识联合的 tag 时极其常用：

```ts
const STATUS = { IDLE: 'idle', LOADING: 'loading' } as const;
type Status = (typeof STATUS)[keyof typeof STATUS]; // 'idle' | 'loading'
```

### 4. 上下文类型（Contextual Typing）

TS 会**根据表达式所处的位置**反推类型——最典型的是事件处理器、回调参数：

```ts
// onClick 的类型来自 JSX 元素的上下文，e 自动是 React.MouseEvent
<button onClick={(e) => { /* e 已被推导为 MouseEvent */ }} />

// arr.map 的回调参数 item，类型来自数组元素类型
[1, 2, 3].map((item) => item.toFixed()); // item: number（无需标注）

// 赋值给带类型的变量时，右侧获得上下文类型
let fn: (x: number) => number = (x) => x * 2; // x: number（上下文推导）
```

上下文类型是「**由外而内**」的推导，与「由内而外」的基础推导互补。

### 5. 泛型推导

调用泛型函数时，TS 从实参反推类型参数（见《泛型》）：

```ts
function first<T>(arr: T[]): T {
  return arr[0];
}
first([1, 2, 3]); // 从 [1,2,3] 推导 T = number，返回 number
first(['a']); // T = string
```

### 6. infer：在条件类型中「声明待推导的槽位」

`infer` 是类型推导的高级形态——在条件类型里**挖一个坑，让 TS 帮你填出坑里的类型**：

```ts
// 提取 Promise 内部的类型
type Unwrap<T> = T extends Promise<infer U> ? U : T;
type A = Unwrap<Promise<string>>; // string

// 提取函数返回值类型（内置 ReturnType 的原理）
type MyReturn<T> = T extends (...args: any[]) => infer R ? R : never;
type B = MyReturn<() => number>; // number

// 提取数组元素类型
type Elem<T> = T extends (infer E)[] ? E : T;
type C = Elem<boolean[]>; // boolean
```

```text
   T extends Promise<infer U> ? U : T
   └──────┬──────┘ └──┬──┘   └┬┘
     模式匹配        待推导槽   匹配成功则返回 U
   含义：如果 T 长得像 Promise<某类型>，就把「某类型」抓出来命名为 U
```

`infer` 是《工具类型》《类型体操》的核心引擎，几乎所有「提取型」工具类型都靠它。

### 7. satisfies：既要校验、又要保留窄类型

`satisfies`（TS 4.9+）解决一个痛点：**用 `: Type` 标注会把类型「放宽」到标注类型，丢失推导出的精确信息；`as` 又是强行断言不校验。** `satisfies` 则「校验是否满足某类型，但保留推导出的精确类型」：

```ts
type Colors = 'red' | 'green' | 'blue';

// ❌ 用 : 标注——palette 的值被放宽为 string | [number,number,number]
const palette: Record<Colors, string | [number, number, number]> = {
  red: [255, 0, 0],
  green: '#00ff00',
  blue: [0, 0, 255],
};
palette.green.toUpperCase(); // ❌ 报错：类型是 string | [..]，不确定有 toUpperCase

// ✅ 用 satisfies——校验结构，同时保留每个值的精确类型
const palette2 = {
  red: [255, 0, 0],
  green: '#00ff00',
  blue: [0, 0, 255],
} satisfies Record<Colors, string | [number, number, number]>;
palette2.green.toUpperCase(); // ✅ green 仍被推导为字面量 '#00ff00'（string）
```

**`satisfies` vs `as` vs `: Type`：**

| 写法          | 是否校验 | 保留窄类型 | 语义                   |
| ------------- | :------: | :--------: | ---------------------- |
| `: Type`      |    ✅    |     ❌     | 标注，放宽到 Type      |
| `as Type`     |   ⚠️弱   |     —      | 断言，强行当作 Type    |
| `satisfies T` |    ✅    |     ✅     | 校验满足 T，保留原推导 |

## 四、实践

### 1. 何时标注、何时推导

```ts
// ✅ 变量：能推导就不标注
const users = fetchUsers(); // 让返回类型自然流动

// ✅ 函数参数与返回值：显式标注（对外契约，也防推导意外）
function formatUser(user: User): string {
  return user.name;
}

// ✅ 需要字面量/只读时用 as const
const ROLES = ['admin', 'user'] as const;

// ✅ 需要「校验 + 精确」时用 satisfies
const routes = { home: '/', about: '/about' } satisfies Record<string, string>;
```

### 2. 用 typeof 从值反推类型

```ts
const config = { host: 'localhost', port: 8080 };
type Config = typeof config; // { host: string; port: number }
```

这让你「先写值、再取类型」，避免类型与实现两处维护。

## 五、常见误区

- **误区一：`const` 和 `let` 推导一样。** `const s = 'a'` 得字面量 `'a'`，`let s = 'a'` 得 `string`——字面量拓宽是关键差异。
- **误区二：到处写标注求「安心」。** 冗余标注既啰嗦又可能与实际值脱节；能推导处应交给编译器。
- **误区三：用 `as` 代替类型收窄。** `as` 是「我比编译器懂」的强行断言，会掩盖真实错误；优先用控制流收窄或 `satisfies`。
- **误区四：`: Type` 标注后以为还保留字面量。** 标注会放宽到标注类型，需要精确值时用 `satisfies` 或 `as const`。
- **误区五：把 `infer` 当运行时反射。** `infer` 只活在编译期的条件类型里，运行时类型已擦除，不能据此做逻辑判断。

## 六、总结

- 类型推导让 TS 在无标注时自动算出类型，是「少写标注、不失安全」的基础能力。
- **字面量拓宽**解释了 `const`（窄）与 `let`（宽）的差异；**`as const`** 主动冻结为最窄只读类型。
- **上下文类型**由外而内推导（事件、回调），**泛型推导**从实参反推类型参数。
- **`infer`** 是条件类型中的「推导槽」，撑起几乎所有提取型工具类型。
- **`satisfies`** 兼得「校验 + 保留精确类型」，优于会放宽的 `: Type` 和会掩盖错误的 `as`。
- 经验：**变量靠推导，函数签名靠标注，常量用 `as const`，配置用 `satisfies`。**

> 类型推导揭示了一个反直觉的真理：**在 TypeScript 里，写得越少，往往越安全。** 让编译器承担推导，你只在「对外契约」与「需要收窄」处点几笔——这才是与类型系统协作的正确姿势，而非和它比拼谁标注得多。
