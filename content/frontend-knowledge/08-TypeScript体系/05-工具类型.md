# 工具类型

## 一、是什么

**工具类型（Utility Types）是 TypeScript 内置的一组「类型转换器」**：输入一个类型，输出一个经过变换的新类型。它们让你基于已有类型快速派生出变体，而无需重复手写。

```ts
interface User {
  id: number;
  name: string;
  email: string;
}

type UserPreview = Pick<User, 'id' | 'name'>; // 只挑两个字段
type UserDraft   = Partial<User>;             // 所有字段变可选
type FrozenUser  = Readonly<User>;            // 所有字段变只读
```

工具类型的背后，是《泛型》《类型推导》讲过的机制——**映射类型、条件类型、`infer`**。本篇不仅列用法，更拆解每个内置类型的实现，让你「知其所以然」，进而能自己造工具类型。

```text
   输入类型  ──▶  [ 工具类型 = 泛型 + 类型运算 ]  ──▶  输出类型
   User              Partial<User>              { id?; name?; email? }
```

## 二、为什么

- **DRY（不重复）**：字段只在源类型定义一次，各种变体自动派生，改一处全联动。
- **精确表达意图**：`Partial<User>` 一眼看出「User 的可选版」，胜过重抄一遍加 `?`。
- **减少错误**：手抄字段易漏易错，派生类型永远与源同步。
- **可组合**：工具类型可层层嵌套，`Readonly<Partial<Pick<User,'id'>>>`，表达力强。

> 典型场景：表单的「创建」（`Omit<User,'id'>`，id 后端生成）、「更新」（`Partial<User>`，只传改动字段）、「只读展示」（`Readonly<User>`）——全都从同一个 `User` 派生。

## 三、核心原理

### 1. 修饰符类：Partial / Required / Readonly

这三个都基于**映射类型（Mapped Type）**——遍历一个类型的每个键并施加变换：

```ts
// Partial：所有属性变可选
type Partial<T> = { [K in keyof T]?: T[K] };

// Required：所有属性变必填（-? 移除可选修饰符）
type Required<T> = { [K in keyof T]-?: T[K] };

// Readonly：所有属性变只读
type Readonly<T> = { readonly [K in keyof T]: T[K] };
```

关键是理解映射语法 `[K in keyof T]: T[K]`：

```text
   keyof User          = 'id' | 'name' | 'email'   （取出所有键的联合）
   [K in keyof User]   = 遍历每个键 K
   T[K]                = 该键原本的值类型（索引访问）
   ?  / readonly / -?  = 施加/移除修饰符

   Partial<User> 展开：
   { id?: number; name?: string; email?: string }
```

### 2. 键的选取与构造：Pick / Omit / Record

```ts
// Pick：从 T 中挑选指定的键
type Pick<T, K extends keyof T> = { [P in K]: T[P] };

// Omit：从 T 中剔除指定的键（= Pick 的补集）
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

// Record：构造一个键为 K、值为 T 的对象类型
type Record<K extends keyof any, T> = { [P in K]: T };
```

```ts
type UserBasic = Pick<User, 'id' | 'name'>;   // { id: number; name: string }
type NewUser   = Omit<User, 'id'>;            // { name: string; email: string }
type Flags     = Record<'a' | 'b', boolean>;  // { a: boolean; b: boolean }
```

注意 `Omit` 的实现——它是 `Pick` + `Exclude` 的组合，这正体现「工具类型可互相搭建」。

### 3. 联合运算类：Exclude / Extract / NonNullable

这三个基于**条件类型 + 分发（distributive）**特性：当条件类型的参数是联合类型时，会**逐个成员分别计算**再合并。

```ts
// Exclude：从 T 中剔除能赋给 U 的成员
type Exclude<T, U> = T extends U ? never : T;

// Extract：从 T中保留能赋给 U 的成员
type Extract<T, U> = T extends U ? T : never;

// NonNullable：剔除 null 和 undefined
type NonNullable<T> = T extends null | undefined ? never : T;
```

**「分发 + never 消失」是它们的魔法核心：**

```ts
type T = 'a' | 'b' | 'c';
type R = Exclude<T, 'a'>;
// 分发过程（T 是联合，逐个算）：
//   Exclude<'a','a'> = 'a' extends 'a' ? never : 'a' = never
//   Exclude<'b','a'> = 'b' extends 'a' ? never : 'b' = 'b'
//   Exclude<'c','a'> = never ... 'c'
// 合并：never | 'b' | 'c' = 'b' | 'c'   ← never 在联合中自动消失！
```

```text
   分发的关键：never 是联合的「单位元」——A | never = A
   所以「被排除的成员变成 never」= 「从联合中消失」
```

### 4. 函数信息提取：ReturnType / Parameters / Awaited

这类靠 `infer` 从函数/Promise 类型中「抓」出内部类型：

```ts
// ReturnType：提取函数返回值类型
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;

// Parameters：提取函数参数类型（元组）
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;

// ConstructorParameters：提取构造函数参数
type ConstructorParameters<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: infer P) => any ? P : never;

// Awaited：递归解开 Promise（TS 4.5+）
type A = Awaited<Promise<Promise<string>>>; // string（自动递归 unwrap）
```

```ts
function getUser() { return { id: 1, name: 'Tom' }; }
type U = ReturnType<typeof getUser>; // { id: number; name: string }

function fn(a: number, b: string) {}
type P = Parameters<typeof fn>; // [a: number, b: string]
```

### 5. 字符串操作类

TS 4.1+ 提供对字符串字面量类型的变换：

```ts
type Hi = Uppercase<'hello'>;    // 'HELLO'
type Lo = Lowercase<'HELLO'>;    // 'hello'
type Cap = Capitalize<'hello'>;  // 'Hello'
type Unc = Uncapitalize<'Hello'>; // 'hello'
```

它们常配合模板字面量类型做「键名转换」（如 camelCase ↔ snake_case，见《类型体操》）。

### 6. 全景速查表

| 工具类型               | 作用                          | 底层机制            |
| ---------------------- | ----------------------------- | ------------------- |
| `Partial<T>`           | 全部属性变可选                | 映射 + `?`          |
| `Required<T>`          | 全部属性变必填                | 映射 + `-?`         |
| `Readonly<T>`          | 全部属性变只读                | 映射 + `readonly`   |
| `Pick<T,K>`            | 挑选部分键                    | 映射 + 约束         |
| `Omit<T,K>`            | 剔除部分键                    | Pick + Exclude      |
| `Record<K,T>`          | 构造键值类型                  | 映射                |
| `Exclude<T,U>`         | 联合中剔除成员                | 条件 + 分发 + never |
| `Extract<T,U>`         | 联合中保留成员                | 条件 + 分发         |
| `NonNullable<T>`       | 剔除 null/undefined           | 条件 + never        |
| `ReturnType<T>`        | 取函数返回值类型              | `infer`             |
| `Parameters<T>`        | 取函数参数元组                | `infer`             |
| `Awaited<T>`           | 递归解开 Promise              | 递归条件 + `infer`  |

## 四、实践

### 1. 组合派生：表单场景全家桶

```ts
interface Article {
  id: string;
  title: string;
  content: string;
  createdAt: Date;
}

type CreateArticle = Omit<Article, 'id' | 'createdAt'>; // 新建：去掉后端生成字段
type UpdateArticle = Partial<Pick<Article, 'title' | 'content'>>; // 更新：只改可编辑字段且可选
type ArticleView   = Readonly<Article>;                  // 展示：只读
```

### 2. 自造工具类型：DeepPartial

内置 `Partial` 只作用于第一层。需要递归可选时，用**递归 + 条件类型**自己写（《类型体操》详述）：

```ts
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;
```

### 3. 用 keyof + typeof 从常量派生联合

```ts
const ENV = { dev: 'development', prod: 'production' } as const;
type EnvKey = keyof typeof ENV;       // 'dev' | 'prod'
type EnvVal = typeof ENV[EnvKey];     // 'development' | 'production'
```

## 五、常见误区

- **误区一：`Partial` 是深递归的。** 内置 `Partial` 只让**第一层**属性可选，嵌套对象内部不变；需要深层用 `DeepPartial`。
- **误区二：`Omit<T, K>` 的 K 不受约束会拼错。** `Omit` 的 `K extends keyof any`（宽松），拼错键名**不报错**、静默无效；对 `Pick` 才有 `keyof T` 强约束。想要严格可自定义 `StrictOmit`。
- **误区三：条件类型对联合一定分发。** 分发**只对「裸类型参数」生效**；写成 `[T] extends [U]` 包一层就不分发了——这是控制分发行为的常用技巧。
- **误区四：`Record<string, T>` 保证所有键存在。** 它只约束「值为 T」，不代表任意键都真有值；配合 `noUncheckedIndexedAccess` 才更安全。
- **误区五：把工具类型当运行时函数。** 它们全是编译期类型，运行时不存在，`typeof Partial` 之类的用法无意义。

## 六、总结

- 工具类型是 TS 内置的「类型转换器」，输入类型、输出变换后的类型，实现 DRY 与精确表达。
- 三大底层机制：**映射类型**（`Partial`/`Pick`/`Record` 遍历键）、**条件类型 + 分发**（`Exclude`/`Extract`/`NonNullable`，靠 `never` 在联合中消失）、**`infer`**（`ReturnType`/`Parameters`/`Awaited` 提取内部类型）。
- 工具类型可**互相组合**（`Omit = Pick + Exclude`），也可**自定义扩展**（`DeepPartial`）。
- 注意边界：`Partial` 只作用一层、`Omit` 的键不严格约束、条件类型分发只对裸参数生效。
- 它们全是编译期产物，运行时被擦除。

> 工具类型的真正价值，不在于「记住 Partial、Pick 怎么用」，而在于**看懂它们由映射类型、条件类型、`infer` 搭建而来**——一旦掌握这三块积木，你就不再是工具类型的「使用者」，而能随手造出属于自己的类型工具。下一篇《类型体操》，正是这套积木的极限运用。
